# PuzzleDB-Go Project Overview

PuzzleDB is a high-performance, distributed, cloud-native **multi-model database** implemented in Go. It supports multiple data models (key-value, relational, document) and exposes existing wire protocols (PostgreSQL, MySQL, Redis, MongoDB, gRPC) over a unified internal key-value storage engine.

## Core Architecture

### Plugin-Based System
The server is built on a modular plugin architecture. Capabilities are implemented as `Service` implementations registered and managed by a `PluginManager`.

- **Exclusive Services:** Only one active at a time (e.g., coordinator, KV store, document/key coders).
- **Non-Exclusive Services:** Multiple can run concurrently (e.g., query protocols, auth, tracing, metrics).

Service lifecycle: `SetConfig` → `Start` → `Stop`.

### Storage & Data Model
- **Internal Model:** All data (relational, document, KV) maps to an **ordered key-value store**.
- **Storage Engines:** FoundationDB (distributed, ACID) for production; memdb for local dev/testing.
- **Encoding:** Documents use CBOR (`coder/document/cbor`); keys use tuple encoding (`coder/key/tuple`).

### Query Protocols
Each supported protocol is a query plugin under `puzzledb/plugins/query/`:
- **PostgreSQL:** Port 5432
- **MySQL:** Port 3306
- **Redis:** Port 6379
- **MongoDB:** Port 27017
- **SQL Execution:** Shared logic in `plugins/query/sql/` used by PostgreSQL and MySQL.

## Key Commands

```bash
make build        # Build server and CLI binaries
make install      # Install binaries to $(GOPATH)/bin
make run          # Install and start puzzledb-server locally
make format       # Regenerate version file + gofmt -s
make lint         # Run golangci-lint
make unittest     # Run all tests with coverage
make test         # Full gate: format → lint → unittest
make certs        # Generate test TLS certs (required for integration tests)
make proto        # Regenerate protobuf Go files
```

## Development Conventions

### Error Handling
Sentinel errors are defined in `puzzledb/errors.go`. Use `errors.Is` and `errors.As` for checking, and wrap errors with context.

### Testing
- **Integration Tests:** Located in `puzzledbtest/`, using a real server instance via `puzzledbtest.NewServer()`.
- **Naming:** Use `UnixNano()` timestamps for unique database names in tests to avoid collisions.
- **TLS:** Run `make certs` before running tests that require TLS.

### Code Generation
- `puzzledb/version.go`: Auto-generated by `make format`.
- Protobuf: Generated from `puzzledb/api/proto/v1/` via `make proto`.

## Directory Structure

- `puzzledb/`: Core library (auth, cluster, coordinator, plugins, stores).
- `puzzledbtest/`: Integration test helpers and suites.
- `cmd/`: Entrypoints for `puzzledb-server` and `puzzledb-cli`.
- `doc/`: Architecture documents, specifications, and protocol guides.
- `api/`: Protobuf definitions and generated code.

## Technology Stack
- **Go:** version 1.25+
- **Primary Dependencies:** FoundationDB, Ristretto (cache), Cobra/Viper (CLI/Config), gRPC.
- **Internal Libraries:** Heavily uses `github.com/cybergarage/go-*` suite for logging, tracing, SQL parsing, and protocol handling.
