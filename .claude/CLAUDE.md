# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

PuzzleDB is a high-performance, distributed, cloud-native **multi-model database** written in Go. It exposes multiple existing wire protocols (PostgreSQL, MySQL, Redis, MongoDB, gRPC) over a single unified internal key-value storage engine.

## Commands

```bash
make build        # Build server and CLI binaries
make install      # Install binaries to $(GOPATH)/bin
make run          # Install and start puzzledb-server locally
make format       # Regenerate version file + gofmt -s
make lint         # golangci-lint on puzzledb/, puzzledbtest/, cmd/
make unittest     # Run all tests with coverage (no lint)
make test         # Full gate: format → lint → unittest
make certs        # Generate test TLS certs (required before integration tests)
make proto        # Regenerate protobuf Go files
```

**Running a single test:**
```bash
go test -v ./puzzledb/cluster -run TestClockCompare
go test -v ./puzzledbtest/plugins/query/postgresql -run TestPostgreSQLServer
go test -v ./puzzledbtest/plugins/query/postgresql -run "TestPostgreSQLServer/authenticator"
```

Before opening a PR, run `make certs && make unittest` to match CI behavior.

## Architecture

### Directory Structure

- `puzzledb/` — core library: auth, cluster, coordinator, config, document model, store interfaces, plugin manager, and all plugin implementations
- `puzzledbtest/` — integration test helpers and suites (no production code)
- `cmd/` — binary entrypoints: `puzzledb-server`, `puzzledb-cli`
- `doc/` — architecture docs, specs, protocol docs, generated CLI/API docs
- `scripts/` — utility scripts (FoundationDB setup helpers)

### Plugin System

The entire server is built around a **plugin manager** (`puzzledb/plugins/`). Every capability is a `Service` implementation registered at startup in `Server.reloadEmbeddedPlugins()` (`puzzledb/server.go`).

Every plugin implements:
```go
type Service interface {
    SetConfig(config config.Config)
    ServiceType() ServiceType
    ServiceName() string
    Start() error
    Stop() error
}
```

Service types are either **exclusive** (only one active: coordinator, KV store, coders) or **non-exclusive** (multiple can run: query protocols, auth, tracing, metrics). Plugin lifecycle: `SetConfig` → `Start` → `Stop`.

New plugins go under `puzzledb/plugins/<category>/<name>/` matching existing domain structure. Package boundaries align with service types: `store/`, `query/`, `coordinator/`, `auth/`, `tracer/`, `metrics/`.

### Storage Model

All data models (relational, document, key-value) map to a single **ordered key-value store** internally:
- **FoundationDB** (`plugins/store/kv/fdb/`) — distributed, ACID, production use
- **memdb** (`plugins/store/kv/memdb/`) — in-memory, for local dev/testing

Documents are encoded with **CBOR** (`plugins/coder/document/cbor/`); keys use **tuple encoding** (`plugins/coder/key/tuple/`).

### Query Protocols

Each wire protocol is a separate query plugin under `plugins/query/`:
- `postgresql/` — port 5432
- `mysql/` — port 3306
- `redis/` — port 6379
- `mongo/` — port 27017

SQL execution is shared in `plugins/query/sql/` and used by both PostgreSQL and MySQL plugins.

### Cluster Coordination

The coordinator (`plugins/coordinator/`) manages cluster membership and messaging, mirroring the KV store choice: FoundationDB coordinator for distributed mode, memdb coordinator for local mode. An etcd coordinator is also available (`plugins/coordinator/core/etcd/`).

## Key Conventions

### Error Handling

Sentinel errors are defined in `puzzledb/errors.go`. Use wrapping helpers:
```go
var ErrNotFound = errors.New("not found")
// Wrap:
return fmt.Errorf("%v is %w", target, ErrNotFound)
// Check:
if errors.Is(err, ErrNotFound) { ... }
```

### Testing Patterns

Integration tests in `puzzledbtest/` use a real server instance:
```go
server := puzzledbtest.NewServer()
err := server.Start()
defer server.Stop()
```

Use `UnixNano()` timestamps for unique database names to prevent test collisions:
```go
dbName := fmt.Sprintf("testdb%d", time.Now().UnixNano())
```

Prefer **table-driven tests** for protocol and storage behavior.

### Code Generation

- `puzzledb/version.go` is auto-generated by `make format` — do not edit manually.
- Protobuf files in `puzzledb/api/proto/v1/` generate `.pb.go` via `make proto`.

### Commit Style

Prefer concise, imperative commit subjects. Common patterns: `refactor(scope): ...`, `style: ...`, `Update ...`, `Update doc: <path>`. Keep commits scoped; separate refactors, style-only changes, and doc updates.
